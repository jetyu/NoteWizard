## Context

智能写作目前共用一个总开关：总开关开启后，编辑器既提供用户主动触发的右键写作操作，也会在普通输入停顿后主动请求行内补全。`autoContinue` 仅参与“接受一条 AI 建议后是否再次请求”的分支，而普通输入补全只检查总开关；因此界面中的“自动续写”无法关闭用户理解中的自动预测。

`triggerMode` 决定普通输入补全的等待与冷却时间，`writingStyle` 和 `writingScenario` 只进入自动补全提示词，右键改写、扩写、精简、总结与翻译使用独立的固定任务提示词；`quickTranslationTarget` 则只服务编辑器右键翻译。产品上语调风格与应用场景属于全局写作偏好，当前执行链和设置页都没有表达这一点。

## Goals / Non-Goals

**Goals:**

- 让 `autoContinue` 成为全部输入触发补全的统一开关。
- 关闭自动续写时立即停止待执行或进行中的补全，并清除已有行内建议。
- 保持右键写作操作只受智能写作总开关控制。
- 让语调风格与应用场景共同约束自动续写和右键智能写作输出。
- 用设置分区和控件禁用状态准确表达配置的从属关系。
- 沿用现有持久化字段与默认值，不引入设置迁移。

**Non-Goals:**

- 不改变右键改写、扩写、精简、总结或翻译各自的任务目标和结果替换流程。
- 不允许全局偏好覆盖翻译目标语言、忠实性或各操作的核心任务约束。
- 不新增自动续写模式、模型参数或独立的连续补全开关。
- 不修改自动补全的结构化内容过滤、请求超时或建议接受机制。

## Decisions

### 1. 在自动补全编排边界统一检查总开关与自动续写开关

普通输入和接受建议后的变化都继续进入同一个自动补全 composable，但 composable 只有在 `aiAssistant.enabled` 与 `aiAssistant.autoContinue` 同时为真时才安排请求。编辑器同时观察这两个值；任一值关闭时调用现有清理能力，取消计时器与在途请求并移除建议。

这比只在 `EditorPane` 的普通输入分支增加条件更可靠，因为自动补全的公共入口不会因未来新增调用方而绕过开关。备选方案是新增持久化字段区分“输入预测”和“接受后连续预测”，但这会保留用户难以区分的两个概念，不符合本次语义收敛目标。

### 2. 保留触发策略与连续补全的现有时序差异

专注、标准、积极三种策略继续控制普通输入停顿后的首次预测及冷却时间。用户接受建议属于明确的继续写作信号，自动续写开启时仍使用现有的短延迟继续预测，不额外等待普通输入的冷却周期。

设置文案将“协作策略”改为更明确的“触发策略”，说明其控制停止输入后的触发频率，避免暗示它影响右键操作或网络响应速度。备选方案是让接受建议后的预测也使用模式延迟，但专注模式会在用户已经明确接受建议后仍等待较长时间，削弱连续写作体验。

### 3. 按实际作用域划分四个设置区域

- **基础设置**：智能写作总开关、智能写作模型服务。
- **写作偏好**：语调风格、应用场景。
- **自动续写**：自动续写开关、触发策略。
- **快捷操作**：快速翻译目标语言。

区域按作用范围和使用普适性排序：基础配置优先，其次是同时影响自动续写与右键操作的全局写作偏好，再展示可选的自动续写能力和快捷操作。区域标题与间距样式保留在 `AIAssistantSettings.vue` 内，复用现有设置卡片与控件样式，避免为单页布局扩展全局样式。触发策略保持可见但在总开关或自动续写关闭时禁用；写作偏好和快捷操作只跟随智能写作总开关，关闭自动续写后仍可用于右键操作。隐藏从属配置会使功能不易发现，因此禁用时保留已选值和可见性。

### 4. 在 Main 端统一组合任务提示词与全局写作偏好

Renderer 继续只发送右键操作的 preset 和翻译目标，不新增可被篡改或与持久化设置不一致的偏好字段。Main 在解析当前智能写作配置后，将 `writingStyle` 与 `writingScenario` 传入编辑器提示词构建器。

自动续写和右键操作复用同一组中英文写作偏好片段，避免两套风格、场景文案逐渐分叉。右键提示词先声明操作目标和输出约束，再追加“在不违背操作目标、原意和语言要求的前提下”应用偏好；因此翻译目标语言与忠实性、总结准确性等任务约束具有更高优先级。

备选方案是在 Renderer 生成全局偏好提示词，但这会重复 Main 的提示词职责并允许 UI 状态与 Main 已归一化配置不一致，因此不采用。

### 5. 沿用现有持久化值

不修改设置结构、默认值或归一化逻辑。已有值为 `true` 的用户保持当前自动预测体验；已有值为 `false` 的用户升级后将不再收到普通输入触发的补全，这正是新界面承诺的语义。

简体中文语言包增加区域标题，并调整自动续写、触发策略及全局写作偏好相关说明；其他语言沿用既有键值或默认回退，遵循项目当前只同步简体中文文案的规则。

## Risks / Trade-offs

- [曾关闭“自动续写”但依赖首次补全的用户会观察到行为变化] → 这是修复语义不一致的预期变化；保留设置值并通过清晰说明呈现新行为。
- [关闭开关时请求可能已经到达 Main 进程或远端服务] → Renderer 中止并使请求序列失效，确保迟到结果不会重新显示；不扩展为新的跨 IPC 取消协议。
- [分区增加页面纵向高度] → 使用紧凑标题和现有 8px 卡片间距，不引入嵌套卡片或折叠交互。
- [全局偏好可能与具体右键任务发生冲突] → 在提示词中明确任务目标、原意、翻译语言和忠实性优先，全局偏好仅在兼容范围内生效。
- [仅更新简体中文会使其他语言暂时保留旧名称] → 遵循仓库 i18n 规则，保持现有键兼容，后续翻译可独立补齐。

## Migration Plan

1. 更新 Renderer 自动补全开关判断与配置监听。
2. 重排设置卡片、增加区域标题并更新简体中文文案。
3. 在 Main 端复用写作偏好片段，并将当前偏好加入右键智能写作提示词。
4. 增加回归测试并执行 Main 构建、单元测试、类型检查与 lint。

回滚时恢复 Renderer 判断和设置页结构即可；没有配置结构或数据迁移需要撤销。
