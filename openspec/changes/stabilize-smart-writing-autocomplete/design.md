## Context

自动续写由 `EditorPane` 将 CodeMirror 文档变化转交给 `useAiAssistant`，后者在固定延迟后截取光标前 500 个字符并通过现有 AI Chat IPC 请求完整响应。当前编排只用一个处理中布尔值阻止并发；请求开始后继续输入不会使旧请求失效或针对新内容重新计时。建议状态只在文档变化时清除，选择变化会把同一建议重新绘制到新光标位置；笔记切换也没有独立的文档身份边界。

模型只收到未结构化的光标前文本，Main 提示词固定要求不超过一句话。返回值经 `trim()` 后直接显示，没有原文重叠清理或重复结果拒绝。CodeMirror 变化回调只区分是否接受过 AI 建议，无法区分普通键入、粘贴、历史操作、格式化或外部内容同步；行内建议也只支持整段接受与拒绝。

本变更跨越 Renderer 编辑器扩展、自动续写编排、Bridge 载荷和 Main 提示词，但沿用现有 IPC 通道、AI 服务与设置结构。

## Goals / Non-Goals

**Goals:**

- 只展示仍匹配当前笔记、文档内容、光标与选区的建议。
- 普通键入期间始终针对最新快照重新计时，同时避免粘贴、撤销、格式化和笔记切换误触发生成。
- 使用标题、当前章节、左右局部上下文和光标位置意图提高建议的连贯性与长度适配。
- 在显示前安全移除原文重叠，并拒绝明显重复最近内容的建议。
- 支持整段、逐词和逐句接受，并在首次建议中说明快捷键。
- 让完整接受后的连续预测遵循当前触发策略并留出用户继续输入的观察时间。

**Non-Goals:**

- 不新增自动续写设置、快捷键配置项或用户可调模型参数。
- 不新增跨 IPC 的远端请求取消协议；失效请求可以在后台结束，但结果不得显示。
- 不增加生成中状态、错误提示或流式幽灵文本。
- 不支持在代码块、表格及现有禁止的结构化 Markdown 位置自动续写。
- 不对模型输出做通用语义改写或额外调用模型进行质量评审。

## Decisions

### 1. 将编辑器文档变化转换为明确的来源事件

`createCodeEditor` 将向上层发送带来源的变化对象，来源限定为普通键入、粘贴、历史操作、格式化、外部同步、AI 部分接受、AI 完整接受或其他变化。分类优先读取 AI 接受和外部同步 Annotation，再读取 CodeMirror `userEvent`；`setValue` 使用外部同步 Annotation，避免笔记内容加载被误判为键入。

所有变化都会使在途结果失效。只有普通键入安排正常预测，只有 AI 完整接受安排连续预测；粘贴、历史操作、格式化、外部同步、其他变化和 AI 部分接受不主动请求。备选方案是在 `EditorPane` 通过 DOM 的 `paste`、键盘事件推断来源，但无法覆盖工具栏命令、撤销和程序化 dispatch，因此不采用。

### 2. 用请求序列与完整编辑器快照保证新鲜度

自动续写编排在每次内容、纯选择或笔记身份变化时递增请求序列、清除已有计时器并按需清除建议。每个请求捕获笔记 ID、完整文档文本、光标位置和空选区状态；结果返回时同时检查请求序列、当前笔记身份、当前文档、当前光标和选区。任一项不一致时丢弃结果。

普通键入即使发生在旧 IPC 请求执行期间，也会为最新快照重新安排请求。由于现有 IPC Promise 不支持 AbortSignal，本变更不伪造本地取消；旧请求允许后台结束，但序列检查保证不会覆盖最新状态。相比新增取消通道，这一方案不改变 Main 请求生命周期协议，且直接满足用户可见的新鲜度要求。

### 3. 扩展现有补全载荷而不替换 `context`

保留现有 `context` 字段作为光标前文本以兼容当前调用链，新增可选的 `contextAfter`、`noteTitle`、`sectionHeading` 和 `intent`。Renderer 从完整文档提取：

- 光标前最多 2,000 个字符；
- 光标后最多 500 个字符；
- 笔记标题；
- 光标前最近的 Markdown ATX 标题；
- `continue-sentence`、`continue-paragraph` 或 `bridge-text` 续写意图。

中间存在后文时使用 `bridge-text`；光标前以句末标点、空段或换行边界结束时使用 `continue-paragraph`；其余使用 `continue-sentence`。Main 的 Zod schema 为新字段设置长度与枚举约束，并继续允许只有 `context` 的旧载荷。

### 4. 提示词按位置决定长度，并将全局偏好降为兼容约束

Main 根据续写意图构建不同输出要求：句中续写生成短语或至多一句，段尾续写生成同一段内一至两句，中间编辑生成能够同时衔接左右文的短内容。提示词使用明确的标题、章节、光标前后边界，并加入原文重复的正反示例。

删除“严格保持原文语气和写作风格”的绝对约束，改为优先保证语言、事实与上下文连贯，在不造成突兀衔接时应用全局语调风格和场景偏好。这避免原文风格与用户配置互相冲突，同时保留偏好的全局作用域。

### 5. 在 Renderer 设置确定性的结果质量闸门

新增 AI completion Renderer service，集中负责上下文提取和结果清理。清理按以下顺序执行：规范换行与外层空白、移除“原文结尾—建议开头”的最长精确重叠、移除“建议结尾—后文开头”的精确重叠、补足英文单词边界空格、检测建议首句与最近原文片段的字符二元组相似度。清理后为空、只有标点或相似度超过阈值的结果不显示。

只自动删除确定性的精确重叠；近似重复只用于整条拒绝，不尝试语义改写，避免误删用户可能需要的实体或事实。备选方案是只强化提示词，但模型约束不能构成稳定保证，因此仍需本地质量闸门。

### 6. 建议状态保存剩余文本并支持分段接受

行内建议状态从字符串调整为包含文本和可选提示的对象。`Tab` 插入全部文本并标记完整接受；`Ctrl+ArrowRight` 使用 `Intl.Segmenter` 的单词边界插入下一词，`Ctrl+Shift+ArrowRight` 使用句子边界插入下一句，两种部分接受都会保留剩余幽灵文本并标记部分接受。若运行环境无法得到有效分段，则逐词回退到首个连续字符单元、逐句回退到首个句末标点。

快捷键提示由 `EditorPane` 通过 i18n 传入 composable，仅当前编辑器会话第一次成功显示建议时附加，后续建议只显示内容。核心编辑器模块不直接依赖 i18n。

### 7. 完整接受后的连续预测使用策略相关观察期

完整接受后不再固定等待 300ms，而使用当前触发策略普通延迟的 60%，并设置 500ms 下限。观察期内若用户继续键入，新变化会取消连续预测计时并改为针对最新内容的普通键入计时；部分接受不会安排新请求，因为剩余建议仍可继续接受。

这一方案保留“接受建议是强继续信号”，同时避免用户刚接受就立即出现下一条建议。备选方案是完整使用普通模式延迟，但专注模式下反馈过慢，因此使用同一策略的缩短比例。

## Risks / Trade-offs

- [旧请求不能真正停止，快速输入时可能产生短暂并行的远端请求] → 每次重新请求前仍执行防抖，且只允许最新序列显示；不在本次引入新的取消 IPC。
- [完整文档字符串快照比较增加本地复制成本] → 编辑器当前已在每次变化时输出完整字符串；上下文仍限制为 2,000/500 字符，不扩大网络负载到全文。
- [相似度阈值可能拒绝合理的修辞重复] → 仅比较建议开头与最近短片段，并要求足够长度和高相似度；宁可不显示一条建议，也不展示明显重复内容。
- [部分接受快捷键可能与光标移动习惯冲突] → 仅在存在建议时拦截；没有建议时返回 `false`，保留 CodeMirror 默认行为。
- [标题和章节可能包含提示注入式文本] → 它们作为带边界的参考文本进入提示词，不作为系统指令；Main 继续控制系统提示词。

## Migration Plan

1. 增加共享续写意图和扩展 IPC 载荷的可选字段，保持旧 `context` 调用有效。
2. 更新编辑器变化来源、建议状态与自动续写编排。
3. 更新 Main schema 与中英文自动续写提示词。
4. 增加回归测试并运行 Main 构建、Preload 构建、Renderer 类型检查、相关单元测试和 lint。

回滚时可同时恢复 Renderer 载荷与 Main 可选字段解析；没有持久化数据需要迁移或回滚。
